# 회원 관리와 신고 처리

관리자 계정으로 로그인한 후 `/admin`에서 이용합니다. PC에서는 왼쪽 관리자 페이지 메뉴, 모바일에서는 설정 화면의 관리자 페이지 버튼으로 이동할 수 있습니다.

## 회원 관리

- **가입 승인:** 새 가입자는 승인 대기로 등록됩니다. 로그인과 설정은 가능하지만 칭찬 작성·공감·신고는 승인 후 가능합니다. 승인 전에는 공개 회원 목록에 표시되지 않습니다. 기존 회원은 승인된 상태를 유지합니다.
- **내보내기:** 모든 로그인 세션을 종료하고 로그인과 활동을 차단합니다. 받은 칭찬과 회원 프로필은 공개 목록에서 숨겨집니다. 계정과 기록은 보관되며 **이용 복구**로 다시 사용할 수 있습니다. 승인 전 계정을 복구하면 다시 승인 대기 상태가 됩니다.
- **다른 계정에 합치기:** 같은 사람의 계정인지 관리자가 확인한 다음, 남길 활동 중 계정을 선택합니다. 남길 계정의 닉네임과 비밀번호를 유지하고 칭찬·공감·신고 기록을 옮깁니다. 두 계정 모두 로그아웃됩니다. 같은 칭찬에 대한 공감은 오래된 시각의 한 건으로 계산하고, 겹친 신고 사유는 함께 보관합니다. 두 계정 사이의 칭찬은 자기 자신에게 보낸 기록이 되므로 숨김 처리합니다. 합친 계정은 복구하거나 옛 닉네임으로 재가입할 수 없습니다. 합치기는 화면에서 되돌릴 수 없으므로 확인 내용을 확인하고 진행합니다.
- **관리자 지정:** 활동 중인 승인 회원을 관리자 계정으로 지정할 수 있습니다. 지정된 관리자는 가입 승인, 회원 관리, 신고 처리를 할 수 있고 처리 기록에 남습니다. 관리자 계정은 내보내거나 다른 계정과 합칠 수 없습니다.
- **비밀번호 초기화:** 활동 가능한 일반 회원(승인 대기 포함)의 카드에서 **비밀번호 초기화**를 누릅니다. 관리자 본인의 현재 비밀번호와 회원의 새 비밀번호를 두 번 입력한 뒤 실행합니다. 새 비밀번호는 10~64자, UTF-8 기준 72바이트 이내여야 합니다. 관리자 계정은 본인이 설정에서 변경해야 하며, 비활성 회원은 먼저 이용 복구가 필요하고 통합된 계정은 초기화할 수 없습니다.
- 관리자 계정은 내보내거나 합칠 수 없습니다. 회원 상태 변경과 합치기는 처리한 관리자와 함께 기록됩니다.

닉네임과 비밀번호만으로 가입하므로 동일인을 자동 식별하지 않습니다. 다른 닉네임으로 다시 신청할 수는 있지만 관리자가 승인하기 전에는 활동할 수 없습니다.

관리자는 칭찬 전송의 1분 대기, 수신자별 하루 3회, 전체 하루 10회 제한을 받지 않습니다. 일반 회원은 기존 제한을 유지합니다. 관리자도 본인이나 활동할 수 없는 계정에 전송할 수 없으며, 메시지 길이·칭찬 유형 검사는 그대로 적용됩니다.

## 비밀번호 초기화 후 안내

초기화하면 해당 회원의 모든 기기에서 로그아웃되고 이전 비밀번호로 로그인할 수 없습니다. 새 비밀번호를 회원에게 직접 전달하고, 로그인 후 **설정 → 비밀번호 변경**에서 본인만 아는 비밀번호로 변경하도록 안내합니다. 비밀번호 자동 발송이나 다음 로그인 시 변경 강제는 없습니다. 가입 승인 상태와 칭찬·공감 기록은 유지합니다.

비밀번호는 bcrypt cost 12 해시로 저장합니다. 처리 기록에는 관리자·대상 닉네임·시각만 남기고 비밀번호나 해시는 API 응답과 기록에 포함하지 않습니다. 관리자 비밀번호 확인을 포함한 요청은 관리자별 15분에 5회까지 가능하며, 초기화 완료 시 대상 닉네임의 로그인 실패 제한을 해제해 다시 로그인할 수 있도록 합니다.

`POST /api/admin/reset-password`는 로그인·승인된 관리자 권한·동일 출처 요청·관리자 비밀번호를 검사합니다. `userId`, `chatNickname`, `currentPassword`, `password`, `confirmPassword`를 JSON으로 받습니다. 대상 상태와 관리자 세션을 트랜잭션에서 다시 검증하고, 비밀번호 저장·모든 세션 만료·처리 기록을 함께 반영하거나 함께 취소합니다. 초기화와 겹친 이전 비밀번호 로그인·비밀번호 변경도 완료 후 유효한 세션이나 비밀번호를 복구할 수 없습니다.

## 익명성과 신고

일반 공개 목록, 받은 칭찬, 회원 프로필과 관리자 전체 칭찬 목록에는 작성자를 전달하지 않습니다. 수신자만 본인이 받은 공개 칭찬을 신고할 수 있습니다. 신고를 접수하면 관리자 **신고** 탭에 메시지·작성자·수신자·신고 사유가 표시됩니다. 신고한 수신자에게도 작성자는 공개되지 않습니다. 신고가 접수되었다고 메시지가 자동으로 숨겨지지는 않으며 관리자가 **메시지 숨기기** 또는 **검토 완료**로 처리합니다.

## 배포

운영 DB 백업 후 `wrangler.d1.json`으로 미적용 마이그레이션을 적용하고 앱을 배포합니다. 비밀번호 초기화 기능에는 `drizzle/0005_admin_password_reset.sql`이 필요합니다. 기존 비밀번호·회원·처리 기록을 유지하며 처리 기록의 DB 검증 규칙만 확장합니다. 기존 회원 관리 작업도 그대로 사용할 수 있습니다. 기록 이전은 D1의 단일 batch 트랜잭션으로 처리하며, 상태를 다시 검증하는 DB 트리거가 실패하거나 이전 중 오류가 발생하면 전체 작업을 롤백합니다.

`npm run test:members`는 임시 DB에서 승인·권한·내보내기·합치기·신고·익명성 검증을 실행합니다. `npm run test:feed`는 기존 칭찬 목록과 공감·날짜 필터를 검증합니다.

`npm run test:password-reset`은 별도 임시 DB에서 관리자 재인증, 입력 검증, 권한·대상 제한, 전체 기기 로그아웃, 새 비밀번호 로그인, 처리 기록의 비밀번호 비공개, 트랜잭션 롤백, 요청 제한을 확인합니다. 초기화와 동시에 진행되는 로그인·비밀번호 변경·관리자 권한 변경·세션 만료도 정확한 DB 경계에서 재현해 검사합니다.
